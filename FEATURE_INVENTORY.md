## 0. Conventions

- **Règle n°1** (PARTIE I) : ne jamais détruire l'existant. Aucune ligne de ce document ne porte la décision DELETE ; les éléments non utilisés (composants orphelins, règles mortes) sont **PRESERVE** par défaut.
- **Décision** (I.4) : **PRESERVE** = conserver tel quel · **AUGMENT** = garder la base, ajouter des capacités · **ELEVATE** = garder fonction, rôle, données, intention ; améliorer la réalisation. Toute insertion nouvelle suit II.7 (nouveaux fichiers, diff minimal, feature flag).
- **Utilisateur** : `visiteur` (public, non connecté) · `client connecté` (compte Supabase) · `admin global` (ligne dans `app_admins`) · `système` (build, CI, base, triggers).
- **Abonnement concerné** : aujourd'hui **aucune fonctionnalité n'est gatée** par un abonnement (grep `quota|plan_id|tier|upgrade` dans `src/` hors `pricing.ts` : 0 ; RLS sans condition de plan, `supabase/migrations/20260615201942_clair_dossier_init.sql:52-63`). La colonne indique donc « aucun (non gaté) » puis, le cas échéant, le plan marketing qui **vend** cette capacité sur `/tarifs` (`src/data/pricing.ts`).
- **État** : `fonctionnel` (fait ce qu'il annonce) · `partiel` (fonctionne avec des manques documentés) · `simulé` (apparence sans traitement réel) · `statique` (contenu / rendu sans logique métier).
- **Test associé** : le dépôt ne contient **aucun test** ni lint (`package.json:6-12` : `dev`, `gen:md`, `build`, `preview`, `typecheck` ; aucune dépendance vitest/jest/playwright ; `find` sur `*.test.*`/`*.spec.*` : 0). Chaque ligne porte donc « aucun — à créer » ; la matrice de non-régression (Phase 0D) reprendra ces IDs.
- **À VÉRIFIER** signale un fait non vérifiable depuis le dépôt (état du projet Supabase live, dashboard Stripe, paramètres GitHub Pages).
- Chemins relatifs à la racine du dépôt ; numéros de ligne à HEAD `24e1e2b`. Les migrations sont abrégées : M1 = `…20260615201942_clair_dossier_init.sql`, M2 = `…20260617110728_dossier_lead_notification.sql`, M3 = `…20260621144123_admin_global_access.sql`, M4 = `…20260622062648_admin_user_emails.sql`, M5 = `…20260628093000_dossier_deliverables.sql`, M6 = `…20260701093000_admin_delete_documents.sql` (toutes sous `supabase/migrations/`).
